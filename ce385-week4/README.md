## Workshop 3 (ce385-week4)

1. `ex1-callback.js` — ระบบตรวจทะเบียน (Error-first Callback)

- สร้างฟังก์ชัน `fetchStudentById` รับ `id` และ `callback` หน่วงเวลา 300ms ด้วย `setTimeout`
- มีระบบ Validate ข้อมูลเข้า ถ้า `id` ไม่ใช่ string หรือหาไม่เจอ จะส่ง `new Error()` เข้า callback ทันที
- ถ้าพบข้อมูล จะส่ง `null` ในช่อง error และส่งวัตถุข้อมูลนักศึกษาแบบตื้น `{ ...student }`
- วนลูปทดสอบครบทั้ง 3 เคส (id มีจริง, id ไม่มีจริง, id ผิดประเภท)
- ตอบคำถามท้ายไฟล์เกี่ยวกับการอ่านค่า property โดยไม่เช็ค error และความจำเป็นของการใส่ `return`

2. `ex2-promise.js` — แปลง Callback เป็น Promise

- เขียนฟังก์ชัน `fetchStudentByIdAsync` คืนค่าเป็น `Promise` (โดยไม่ใช้คีย์เวิร์ด `async`)
- เรียกใช้งานด้วย `.then()`, `.catch()`, และ `.finally()` ครบทั้ง 3 เคส
- ทำ Promise Chain 3 ขั้น: รับข้อมูล -> คำนวณเกรด -> สร้างข้อความรายงาน -> พิมพ์ออกทาง console
- เขียนฟังก์ชัน `promisify` อเนกประสงค์สำหรับแปลงฟังก์ชันรูปแบบ callback ให้คืนค่าเป็น Promise

3. `ex3-async-await.js` — async/await และลำดับ vs ขนาน

- เปรียบเทียบการดึงข้อมูล 3 รายการแบบ sequential (ใช้ `for...of` + `await`) กับแบบ parallel (ใช้ `Promise.all` + `.map`)
- วัดเวลาการทำงานจริง พบว่าแบบขนานทำงานเร็วกว่าแบบตามลำดับประมาณ 3 เท่า
- สร้างฟังก์ชัน `safeReport` หุ้มด้วย `try-catch-finally` เพื่อจัดการ error โดยไม่ให้โปรแกรมพัง
- ตอบคำถามท้ายไฟล์เรื่องความแตกต่างระหว่าง `try-catch` กับ callback และผลกระทบจากการลืมใส่ `await` หน้า `Promise.all`

4. `ex4-combinators.js` — เลือก Combinator ให้ถูกงาน

- เลือกใช้ Promise Combinators ตามสถานการณ์ที่เหมาะสม:
  - สถานการณ์ที่ 1: หน้าแรก ใช้ `Promise.all` เพราะต้องการข้อมูลครบทุกส่วน ถ้ามีส่วนใดล้มเหลวจะเปิดไม่ได้ทันที
  - สถานการณ์ที่ 2: แจ้งเตือนผลสอบ ใช้ `Promise.allSettled` เพื่อให้ทราบสถานะทุกช่องทางโดยไม่พังตามช่องทางที่ล้มเหลว
  - สถานการณ์ที่ 3: Mirror Server ใช้ `Promise.any` เพื่อดึงข้อมูลจากเครื่องแรกที่ทำงานสำเร็จ
  - สถานการณ์ที่ 4: ค้นหาฐานข้อมูล ใช้ `Promise.race` แข่งเวลากับ timeout 800ms หากเกินเวลาจะดึงข้อมูลจากแคชเก่าแทน
